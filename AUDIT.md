**2026-10-24 — SQLite deferred-transaction upgrade race (flake #3, fixed same day).**
Third environment-flake of the project (M3 bootstrap races, M5 PG pool contention, now this) — per the director's watch item it is recorded here. `demote_org_admin_guarded` opened a DEFERRED sqlx transaction: the admin-count SELECT took a read snapshot, and the guarded UPDATE then had to upgrade to a write lock. Two concurrent cross-approvals (the F3 mutual-demote attack window) hit SQLite's BUSY_SNAPSHOT — which ignores `busy_timeout` (it is a deadlock-style refusal, not a wait) — so BOTH executes failed and both actions were marked rejected (0,2) instead of one-executes-one-refuses. Impact: correctness of the last-admin invariant was never at risk (both directions refuse), but the race test could flake and a legitimate demote pair could be spuriously rejected. Fix: the SQLite arm now runs `BEGIN IMMEDIATE` on a held connection (write lock BEFORE the read), so contenders queue on busy_timeout and the count guard arbitrates exactly as on Postgres. Verified 3/3 consecutive runs of `adv_d33_mutual_demote_never_leaves_org_adminless`. Location: `crates/control/src/db.rs` (`demote_org_admin_guarded`).
